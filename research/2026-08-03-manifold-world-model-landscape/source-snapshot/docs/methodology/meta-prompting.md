# Meta Prompting

## 1. 先写“约束所有指令的指令”

这项研究没有把题目直接交给模型并等待一份市场报告。动手检索之前，我先写了一份章程：它不回答“海外世界模型有哪些玩家”，而是规定任何后续指令可以做什么、不可以做什么、何时必须停下、谁有权批准。这就是 Meta Prompting——提示词的对象不是研究问题本身，而是研究过程。

## 2. 三层结构

| 层 | 文件 | 作用 |
|---|---|---|
| 问题层 | DR-01、DR-02、DR-03 | 三个互相制衡的问题：Manifold 的公开锚点、非中国玩家发现池、大厂项目与替代路线。三份报告只作线索 |
| 章程层 | [`项目执行计划`](../../archive/manifold-world-model-landscape/01_inputs/governance/Manifold_World_Model_Research_Project_Plan_v2.0_CN.md) | 20 节（第 0–19 节）。硬约束、摄取规则、资格门、证据标准、权威文件、状态与恢复协议、角色与返回格式、检查点与决策权限、放行条件、完成定义 |
| 启动层 | [`启动 Prompt`](../../archive/manifold-world-model-landscape/01_inputs/governance/Manifold_ChatGPT_Work_Launch_Prompt_v2.0_CN.md) | 三段话。指定唯一的 Research Director，把章程立为最高依据，重申硬约束，并要求在检查点 1 暂停 |

启动 Prompt 之所以可以只有三段，是因为所有判断标准都已写在章程里。执行环境换一个窗口、中断后恢复，读到的仍是同一份章程和同一个状态文件。

## 3. 章程规定了什么

| 章程条款 | 内容 | 防止的问题 |
|---|---|---|
| 硬约束 | 演示稿不超过 10 页；固定五席，3–4 家创业公司加 1–2 个大厂项目；Manifold 只作锚点；类别外对象不入池 | 研究范围在执行中自行扩张 |
| 摄取规则 | 三份 DR 是 lead memo；影响资格、五席或关键数字的主张必须重新打开原始来源 | 二手转述被写成事实 |
| 权威文件 | 每个决策域只有一个权威文件；CSV 与 Markdown 高于其 XLSX、PPT 派生版本 | 多份互相矛盾的“事实库” |
| 状态与恢复 | `project_state.json` 记录阶段、状态、下一步和已批准的检查点；恢复时先读状态；沉默不构成批准 | 依赖聊天语境判断进度 |
| 角色与返回格式 | 一个 Lead 加至多三个并行角色；只有 Lead 写权威文件；每个角色按 15 个字段返回结论、证据、反证和未知 | 并行结果被直接拼接成结论 |
| 检查点与决策权限 | 两个研究检查点、Content Lock 和最终验收；建议者与批准者分列，批准权归研究设计者 | 执行速度越过人的判断 |
| 放行条件 | Red Team 分三路核验；重大问题关闭后方可进入内容锁定 | 报告写得通顺却无法逐条复核 |
| 完成定义 | 五席获批准、主张可追溯、事实与推断分明、Content Lock 获批准、演示稿不超过 10 页 | “做完”没有客观标准 |

## 4. 为什么有效

1. **判断前置。** 资格门、证据阈值和措辞上限在检索开始前就已写定，执行中出现的每一个新对象都按同一标准处理。
2. **停止条件可执行。** 检查点把“可以继续”变成状态文件中的一个字段，审批记录先回写，下游工作才解冻。
3. **输出可以合并。** 统一的返回格式使并行研究的结果能够逐字段比对，冲突在合并时暴露。
4. **人掌握取舍。** 范围、五席和公开措辞由研究设计者批准；工具负责扩大覆盖、恢复来源和重复校验。

这四点共同把一次性的检索任务，变成可以暂停、可以复核、可以交给另一个人重跑的研究系统。
